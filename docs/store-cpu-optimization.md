# 玩家存档 CPU 优化（v3.25.2）

线上存档约 7.4 MB；旧标准库编码在主线程中执行，频繁保存时影响命令和图片响应。
本次只更换全量存档编码，不延长 250 ms 保存合并窗口，不改游戏数值、审计哈希或落盘流程。

使用 orjson 原生编码正常数据块。真实存档存在超出 64 位的资源、属性整数，直接使用
orjson 会失败；遇到这类分支递归分块，只有大整数标量使用标准库精确输出十进制，
其他分支用原生 Fragment 组装。没有把超大资源转成浮点或字符串，也没有在后台线程
读取正在变化的玩家字典。依赖缺失或其他旧类型不兼容时退回标准库。

原子 tmp 写入、长度校验、旧版本 bak 备份、临时宠物引用恢复均保留。
只有玩家存档使用新编码器，审计链继续使用原始标准库编码，避免破坏历史哈希。

2026-10-03 同一服务器、同一真实存档、各三次只读编码对比：

| 编码 | CPU 时间中位数 | 实际耗时中位数 |
| --- | ---: | ---: |
| 标准库 | 782.9 ms | 805.4 ms |
| 原生分块 | 108.5 ms | 109.2 ms |

编码 CPU 时间减少约 86%，所有轮次重新解析后的数据均一致。此结果属于编码环节，
不代表整机 CPU 或出图延迟也下降同样比例；宿主机 steal 仍会影响实际耗时。

复现命令（只读存档，不创建 PetStore 实例、不写玩家数据）：

```powershell
python tools/benchmark_store_cpu.py /path/to/petpark.json --runs 3
```

验证：6 项新增编码/多宠物/合并测试及 4 项原有存档、备份、校验失败保护测试。
原生 Fragment 和大整数范围参考 [orjson 官方文档](https://github.com/ijl/orjson)。
